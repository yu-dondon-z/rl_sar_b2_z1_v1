# VD2 视觉计算周期与后视断段修正（2026-11-06）

## 现场结果与原因

本轮日志 `runs/20261106_120008_042463` 证明 R1+Y 已经进入 tracking，但随后因为
真实采集帧超过 1 s 而停车。有效包计算仍需 624–760 ms；一次推理结束到下一次结果
到达前，正在使用的上一包会超过原有 1 s 限制。`vision=True` 只代表该循环的输入包
检查结果，不能把 braking/return_stand 状态当作还在行走。

另一个独立问题是后视线段选择：许多包的 x 范围只有 `[-0.91,-0.63] m`，未覆盖
训练工作点 `x=-1.02 m`。保存的真实 RGB 中胶带连续，神经掩膜也连续；深度无返回
使地面 ROI 破碎。原来优先靠近图像锚点的分量，可能选择了更近的短段。

## 本次改动与证据边界

1. CPU RHANet 使用 channels_last 存储布局，OpenCV 限制为 1 个线程、torch 仍为 2。
   权重、输入 360×640、相机完整分辨率、0.90 阈值与内外参不变。使用两个原始 RGB
   做板载对照，阈值掩膜没有不同像素，概率最大差异约 7.1e-6。
2. PNG 由有界后台线程保存（最多一个待写任务）。磁盘慢时丢弃诊断保存请求，
   不阻塞相机或推理；原始视觉包日志继续保留。首个有效 `valid_pair_*` 之外，新增
   首个覆盖工作点的 `working_pair_*`、每 5 s 更新的 `latest_valid_*`。每组都保存
   对应原始图、实测深度及该组独立采集时间，不从其他时刻拼图。
3. 后视连通分量优先选择实际观测到且跨过工作 x 的分量。没有这样的分量时仍可报告
   检测，但控制器仍拒绝启动；不外推到工作点，也不把分离线段直接拼接。
4. 仅在实测地面包围的小深度空洞里，允许已检测的 RGB 中心线射线与该帧 RANSAC
   地面相交。支持区最多 12 px 半径、预测物理半径不超过 3 cm、25×25 邻域地面
   支持率至少 35%，排除边界、真实高出地面的物体和其边缘。传感器深度数组不改写。
   路径仍要求至少 65% 的采样点具有原来的 3×3 实测深度支持；投影补点单独计数，
   不能标成真实深度返回。低深度支持、大空洞或实际遮挡仍拒绝。

没有改变 A/Y/B 状态机、站立增益、C++ IO、策略、0.20 m/s 指令、停止恢复、1 s 帧
时效或 40 ms 主机接收配对限制。仍不能用主机接收时间声称曝光同步。
后视测量是焊缝目标，并非视觉测得真实枪尖；精确 TCP 闭环还需要对应测量和验收。

## 使用

此更新安装时校验原文件哈希并保存 `patch_backups/vision_realtime_*`，拒绝覆盖意外
本地改动。无需重新编译 C++。统一入口仍然是：

```bash
cd /home/unitree/rl_sar_b2_z1_VD2
source .venv/bin/activate
bash start_real.sh --interface eth0
```

A 起立、Y 准备到 ready，再看 `[vision]` 的实际帧年龄、processing_ms、后视覆盖。
ready 后 R1+Y 请求视觉跟踪；X/B 和原来的停止逻辑保持。若后视仍不覆盖工作点，
保持 ready，查看新保存的工作视角图像，不靠重复按键或放宽时效绕过。

只测试相机与识别、不启动 Z1 或电机控制：

```bash
python tools/check_visual_stream.py --interface eth0 --seconds 60
```

此命令不能与已有相机程序争用设备；不调用 `vd2_open`、`vd2_acquire` 或指令发送。
它不会替用户起立。趴姿地面空间支持不足时拒绝拟合是正常的，不能据此证明站立后
识别失败或拿快速拒帧时间当作完整网络推理速度。

离线复算真实记录，不打开任何 IO：

```bash
python tools/replay_visual_pair.py --session runs/实际会话目录 --iterations 30 --compare-reference
```

默认优先 working_pair_，其次 latest_valid_，最后 valid_pair_；`--prefix valid_pair_`
可选指定组。`--reference` 单独运行旧计算路径作性能对照。离线保留来源采集时间，
不把旧图伪装成新鲜帧；PNG 深度量化到 1 mm。
