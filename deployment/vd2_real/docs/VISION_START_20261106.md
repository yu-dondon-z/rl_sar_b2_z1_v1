`outputs/VD2_REAL_VISION_START_20261106_YTHOGP/`。Y 能到 ready，R1+Y 事件已识别，

405 个包只有 12 个成对检测有效，但大多数地面拟合失败发生在趴姿，不能把总比例当作站立识别成功率。

## 改动

- RHANet 输入、完整相机分辨率、内外参及识别阈值保留。Zhang-Suen 细化只扫描非零掩膜的
  外接矩形，再写回原图坐标；矩形外全为零，不改变骨架像素或迭代规则。
- PNG 保存移到视觉包投递之后，采用较快的 PNG 压缩，避免先压图再处理所选帧。
  记录前后处理耗时。首次检测有效的同一对原始图、真实深度及独立时间戳保存在
  `valid_pair_*`，避免退出时趴姿覆盖全部诊断资料。
- R1+Y 在 ready 请求等待最多 5 s；只在原有时效和几何条件全部满足时进入 tracking。
  X、B、再次 R1+Y、离开 ready 或等待超时取消。取消/停止后有效帧不能自行启动。
- ready 每秒显示具体拒绝原因、真实帧年龄、处理耗时、后视线段 x 范围，并写入控制日志。
  仍要求帧年龄不超过 1 s，目标仍为 `x=-1.02 m`，不补造线段或更新捕获时间。
- 单终端启动器仅合并两种重复的 SDK 接收超时提示：首条即时输出，之后每 5 s 汇总计数，
  退出时补齐计数。真实断连、native fault、状态转换仍即时显示；`main.log` / `z1.log`
  保存所有原始行。直接运行 `python run.py` 仍会显示 SDK 原始输出。

本次不改变 A/Y/B 的起立、收展臂、回趴状态和增益，不改 C++ 通信、反馈时效、策略权重或速度。

## 现场操作

安装不启动控制，且无需重新编译 C++。保留自动生成的 `patch_backups/vision_start_*`。
操作命令仍是：

```bash
cd /home/unitree/rl_sar_b2_z1_VD2
source .venv/bin/activate
bash start_real.sh --interface eth0
```

A 站立完成、Y 展臂进入 ready 后，先看 `[vision]`，再按 R1+Y。
若提示 `visible rear seam does not cover x=-1.02 m`，检查后视画面中胶带是否连续延伸到工作点；
这时仍保持 ready，不用反复按。不能靠放宽过期门槛或外推目标来宣称跟踪成功。

新会话生成 `valid_pair_*` 后，可以不启动任何机器人/相机 IO 做离线复算：

```bash
python tools/replay_visual_pair.py --session runs/替换为实际会话目录
```

离线复算保留来源时间戳，仅测计算耗时与检测/覆盖；深度 PNG 量化到 1 mm，不代表实时通信或运动验收。

## 验证进度

候选完整副本的 59 项 Python 离线检查通过，包含旧实现逐像素对照、等待/取消/时效/目标覆盖回归，

端到端中心线的掩膜、骨架、路径和采样点逐项相等。

板载 CPU 离线性能夹具（相同保存 RGB 与相同固定平面）前视完整处理由 669–704 ms 降到 232–256 ms，
输出测量逐项相等。旧会话只保存最后的趴姿 RGB，因此夹具中平面来自另一个站立时刻；
此结果只证明计算加速，不能证明现场站立画面时效或几何正确。原现场 1995–2512 ms 是前后视
总耗时，不能与这个前视单项夹具直接当作同条件对比。需要新会话的 `valid_pair_*` 才能复算真实站立画面。
