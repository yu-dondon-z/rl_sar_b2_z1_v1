# v4 / model_10300 MuJoCo 部署

此目录对应 `/home/dong/b2_z1` 的 GitHub `v4`（提交 `14df0c2`）和
`2026-09-13_14-31-05_rear_curve_gait_heading_v5_from10000/model_10300.pt`。
源权重 SHA-256 记录在 `config.json`。`policy.pt` 是导出的 CPU TorchScript
actor；256 组输入与原网络比较，最大输出误差为 0。

## 启动

在 `rl_sar_b2_z1` 根目录执行：

```bash
bash scripts/run_b2_z1_v4.sh
```

也可在 VS Code 选择 **部署 v4：MuJoCo 视觉+焊枪（model_10300）**。
这是本次新增的 MuJoCo Python 入口，调用 MuJoCo 原生物理引擎。
现有 C++ / `robot_lab` 入口仍保留原来的 `model_9600`，没有被替换。

启动后机器人呈趴姿，四腿折叠，Z1 六个关节均处于零位收紧状态，焊枪尚未
安装（仿真中隐藏并关闭其碰撞），等待按键；物理仿真
暂不推进，视觉网络可提前加载。在 **启动程序的终端**
直接按下面的单个按键，**不需要回车**。使用 VS Code 时，先将焦点切到启动该程序的
集成终端；MuJoCo 窗口用于查看仿真和调整视角。

1. `0`：先让 B2 从趴姿平滑站起，再把 Z1 从零位展开到安全的焊枪安装位置。
   焊枪此时仍未安装。这里使用独立的对称 B2 站姿，
   不再把策略训练时的非对称关节参考当作站立目标；只有实际腿关节误差和速度
   达标、终端显示 `Standing settled ... policy handoff enabled` 后才允许下一步。
   起身阶段使用独立的负载站立增益，接入策略后自动恢复训练对应的策略增益。
2. 确认 B2 已站稳、Z1 已到安装位后，在实机上安装并紧固焊枪，再按 `1`。
   仿真会在此时显示并启用焊枪碰撞，然后接入零速度策略；四腿保持对称站姿，
   仅允许机械臂移动到轨迹起始姿态。终端显示 `ready` 后准备完成。
3. `t` / `T`：切换默认模式与轨迹模式。首次按下开始视觉轨迹运动，速度在 4 秒内
   平滑提升，需要已有新鲜有效的视觉路径；再次按下立即关闭跟踪、平滑减速停止。
4. `9`：趴下。实机必须先人工卸下焊枪，然后按 `9`；程序先在站立高度把 Z1
   收回六关节零位，再降低 B2。仿真会自动模拟卸枪。运动中按 `9` 时先平滑停车，
   停稳后才执行收臂和趴下，不会直接折腿。

默认模式保持站立、零速度指令及最后的机械臂目标，不再更新裂缝跟踪目标。
运动停止后四腿会在 1.2 秒内回到对称支撑姿态，Z1 不重新收枪，因此再次按
`T` 时不会产生一次额外的长枪展开运动。
停稳显示 `Default mode: trajectory OFF` 后，再按 `T` 可重新开启轨迹跟踪；减速期间
不会接受重新开启。空格也可减速停止。运动中按 `0` 会先减速，再回到站立阶段。
跳过站立或机械臂准备阶段的 `1` / `T` 按键会被拒绝，终端会说明下一步操作。
在终端按 `Ctrl+C` 或关闭 MuJoCo 窗口退出。程序会恢复终端的输入/回显设置，并关闭自己启动的
视觉进程。红球表示实际 TCP，绿球表示目标 TCP，青色点表示视觉路径。

默认速度指令 0.35 m/s，可用 `--speed 0.25` 调低；这是仿真时间中的指令速度。
视觉进程使用现有 `crack_vision` 环境和 RHACrackNet 权重，默认 GPU 推理，
可传入 `--vision-device cpu`。每次运行创建独立的
`/tmp/b2_z1_mujoco_v4_*` 目录，路径会打印在终端；其中保存视觉日志、叠加图和
`latest_controller_status.json`。

## 与训练接口的对应

- 70 维观测：速度指令 3 + TCP 指令 7 + 机身角速度 3 + 重力投影 3 +
  相对关节位置 18 + 关节速度 18 + 上一帧原始动作 18。
- 18 个关节按 Isaac 的实际动作顺序映射，角速度缩放 0.2，关节速度缩放 0.05。
  MuJoCo 的惯性主轴坐标系和 `base_link` 不同；角速度经世界坐标转换到机身坐标。
- 动作截断到 ±5，再经过 alpha=0.20 的 EMA、0.25 缩放和默认关节位置偏置。
- MuJoCo 物理步长 1 ms，腿部 PD 200 Hz，策略 50 Hz；机械臂使用隐式位置驱动。
- 机械臂朝后，圆柱焊枪长 1.10 m、半径 0.028 m，枪尖与 `ee_site` 对齐。
  圆柱属于现有末端连杆，启用场景碰撞，保留训练时关闭的机器人自碰撞设置。
- 趴姿采用 Z1 收紧零位 `[0, 0, 0, 0, 0, 0]`，此姿态禁止安装长焊枪。
  按 `0` 后的安全安装位约为 `[0, 1.05, -0.93, -0.82, 0, 0]`；按 `1`
  后再向策略对应的焊接起始位过渡。
- Isaac 对零质量 `dummy_target` 自动分配了 **1 kg 默认质量**，训练时已经存在。
  此部署显式复现该属性；圆柱本身不增重，`link_gun` 保持 0.001 kg。
  仿真“卸枪”只切换枪体显示和碰撞，仍保留这 1 kg 训练载荷代理，从而在装枪前
  就以较保守的负载验证起身稳定性，并避免运行中重建 MuJoCo 质量常量。
- 独立生成的物理裂缝地图采用与 Isaac v4 相同的缓弯中心线、2 cm 宽和 5 cm 深，
  交互测试场地缩短为 16 m × 3 m，地形图尺寸与场景坐标范围一致；在线路径
  只保留约 1.2 m 后方和 1.8 m 前方。控制器只读取实时 RHACrackNet RGB-D 结果，
  不读取生成地图时的中心线公式。
- 为减少 GUI 播放时 GPU 的重复渲染和分割负担，视觉桥默认以 10 Hz 更新；
  策略和物理控制仍分别保持 50 Hz 与 200 Hz。必要时可用
  `--vision-rate-hz 15` 调整，但不建议超过 25 Hz。
  如果只需要 MuJoCo 主窗口，可用
  `B2Z1_DISPLAY_VISION=0 bash scripts/run_b2_z1_v4.sh` 关闭额外的 RGB/掩码/轨迹三联窗口。

## 验证

2026-09-13 的完整闭环测试：35 秒仿真前进 8.06 m，墙钟耗时 35.44 秒。
第一秒后机身高度为 0.505–0.531 m，最大倾角 2.21°，13.30 秒开始跟踪
后方缓存裂缝点，没有摔倒。首次启动网络的等待时间包含在这 35 秒内。
这是短程仿真验证，尚未验证完整路线和长时间运行。

加入分阶段按键后，再次通过实际视觉闭环验证：同一 `0 → 1 → T` 流程运行
30 秒仿真，最终前向位置 6.22 m，无摔倒，后方缓存轨迹正常接管。自动检查还
覆盖了提前按 `1` / `T` 被拒绝、起始姿态等待、空格停止、`T` 重启及 `0` 返回站立。

改为趴姿启动后，验证初始机身高度 0.138 m、起立过程最大倾角 6.56°，
接入策略后正常站稳。新的视觉闭环运行 25 秒仿真，最终前向位置 4.94 m，无摔倒。
模式检查覆盖连续多次 `t` / `T` 开关、停止后的零速度及位置保持，以及空格停止。

加入可拆卸焊枪和按 `9` 趴下流程后，自动检查确认趴姿 Z1 六关节回到零位、
焊枪不可见且无碰撞；按 `0` 后机身高度约 0.522 m、起身和展臂最大倾角约
6.96°。完整流程 `趴姿 → 0 → 1 → T → 停止/重启 → 0 → 9 → 趴姿`
通过。18 秒视觉闭环测试正常完成，没有趴倒或侧翻。

终端输入检查使用伪终端向实际控制程序发送 `0 → 1 → t → t（停止）→ t → T（停止）`，验证无需回车、
方向键不会误触发状态切换，以及中断退出后恢复终端设置：

```bash
/home/dong/anaconda3/envs/crack_vision/bin/python scripts/check_b2_z1_v4_terminal.py
```

无视觉的 30 秒站立/行走、角速度坐标变换、TCP 对齐、视觉丢失减速，以及
焊枪物理接触均有可重复检查（测试障碍接触峰值约 260 N）：

```bash
/home/dong/anaconda3/envs/crack_vision/bin/python scripts/check_b2_z1_v4.py
/home/dong/anaconda3/envs/crack_vision/bin/python scripts/run_b2_z1_v4.py \
  --headless --auto-start --mode vision --duration 35 --output /tmp/v4_vision_check.json
```

`--auto-start` 仅用于自动化验证，执行相同的 `0 → 1 → T` 状态切换；默认使用
终端手动按键。无图形窗口时也可从终端控制，例如 `--headless --mode walk --duration 30`。
状态 JSON 的 `stage` 字段记录当前阶段。

`--mode walk` 是固定前向速度指令诊断，不带视觉航向修正；长时间运行会侧向漂移。
常规使用请选择默认的 `vision` 模式。仿真策略与 MuJoCo 配置独立存放，原来的
部署文件和实机入口均保持原样。
