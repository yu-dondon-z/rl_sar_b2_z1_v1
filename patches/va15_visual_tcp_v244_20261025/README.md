# VA15 V2.4.4：修复视觉启停抖动的两个已复现诱因

2026-10-25 独立候选；保留 V2.4.3 和主程序。控制核心、VA15 权重、70/18 观测动作、增益、raw 历史/EMA、关节路由、Y 提前收敛、力矩连续接管、TCP 和停止逻辑全部不变。native 日志中的 V2.4.3 表示沿用控制核心，不是选错策略。

## 本轮原因和改动

实机 outputs/va15_near_walk_1rt8m301 的 9 次 R1+Y 中，3 次启动，约持续 2.75、0.15、14.64 秒；6 次因无有效视觉或不足六帧被拒绝。X/B 和正常退出已由日志及操作者确认，没有记录安全故障锁定。

- **处理时延**：相邻有效图像更新中，24 处前一图像在后一包发布时已超过 500 ms；尚未计入 Inbox 25 ms 轮询。例 264→265 为 538.75 ms，265→266 为 553.07 ms。299→300 发布时 486.55 ms，加轮询/解析即可越过边界，因此短暂启动后立即停止。不是按键漏收或只能走一次。
- **曲线模型偏差**：保存的 rejection_000406_after.jpg 中，真实胶带弯曲，近段强制直线残差 6.755 px，被原 6 px 上限拒绝；二次曲线残差为 2.593 px。不是因此证明整条路径或转向能力已合格。

改动仅在 Python 视觉端：

1. 同一个 RHACrackNet、同一 checkpoint、同一 360×640 输入和原 1920×1080 标定，采用 CPU channels-last 权重布局。没有量化、裁切、改阈值、降低输入分辨率或换网络。启动时以确定性输入做数值对照，不一致就报错，不启动控制。
2. 原直线拟合通过时完全沿用。仅直线不合格时，尝试同一段已有观测点的二次曲线，要求残差 ≤3 px、比直线至少降低 50%、切线斜率变化 ≤2；不能用大弯或锯齿状杂乱点蒙混通过。光流关联保留已确认模型的阶数；宽度、神经置信度、近远覆盖、同线约束不放宽，不把缺失路径外推出来。
3. 发布后异步记录逐帧 guide_packets.jsonl，保留真实 capture/publish 和前一有效图像的年龄，便于下次区分时延、失线和拒绝原因。仍有界、可丢诊断，不阻塞控制或伪造新鲜图像。

**500 ms 时效、400 ms 处理预算、首次六帧、真正失线停止和显式重新启动均未修改。** 实际的短胶带、视野外路径和明显换线仍会拒绝；不宣称现在不会再出现视觉中断。

## 人工视觉实验

使用 PC4 的 NoMachine 桌面交互终端，相机和控制同入口，Z1 自动处理：

```bash
cd /home/unitree/rl_sar_b2_z1 || exit 1
bash diagnostics/va15_visual_tcp_v244_20261025/run_visual.sh eth0 --walk
```

保持无枪/软管，机器人实际趴稳、旧控制退出，运动/收臂范围清空，防跌与急停准备好。

1. 输入大写 RUN，A 起立，实际站稳后 Y，等待机械臂准备和支撑就绪。
2. 确认黄/青点在预定黑色胶带而不是瓷砖缝，持续 PATH IN RANGE；不要推摇杆。
3. R1+Y 开始 0.15 m/s，视觉 yaw 限制 ±0.06 rad/s；先只走约 2～3 秒，由人按 X 停止。不因启动拒绝而连续重复按键。
4. X 或再次 R1+Y 停止。B 请求支撑站稳后趴下，实际趴稳且 Passive 后 Ctrl+C。相机会随会话关闭。
5. 若短测正常，再明确开始较长一次，检查 TCP active=1；active=0 可能是尚未积累到后方的已观测轨迹，不伪造后方路径。TCP 仍采用训练的约 9 cm 目标高度和原限速，未安装枪时不是实际工具接地试验。

同一入口的 --preview 只看相机，不接管；--shadow 是可人工站立但不行走的控制实验，不能当成只读预览。失线后不会自动重启，仍需操作者完成停止、确认正确线后再 R1+Y。P/L1+X 会撤去主动支撑，非日常停止；不要用站立断电/强退替代安全停机。
