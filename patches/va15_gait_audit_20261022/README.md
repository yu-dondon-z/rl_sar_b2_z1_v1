# VA15 无视觉行走分阶段审计（2026-10-22）

本轮只读分析现有实机记录，没有改变实机参数、源代码或策略，没有启动
相机/机器人，也没有同步新的控制补丁。原无视觉受限测试版本保持不变。

证据：`motor_contract_v2_forward_20261022_W7SnQf`，前进记录跨度 3.986 s。
输入快照位于 `inputs/`；完整数字见 `phase_audit.json`。

## 已排除的直接软件原因

- 板载模型散列与部署清单一致；原始训练 checkpoint 为
  `2026-09-28_15-07-31_va15_curriculum_from2500/model_5000.pt`。
- 对全部 244 帧真实策略观测重放原 checkpoint 和板载导出模型。二者输出
  完全一致，与 native 记录的最大绝对差约 1.435e-6。
- 上一帧 bounded raw action 观测完全一致；独立 EMA(alpha=0.2) 重放最大差
  4.79e-7；`default + 0.25 * action` 目标计算最大差 1.73e-7 rad。
- 本次无原始 ±5 限幅、无额外逐关节动作限幅触发。腿部 PD=160/5 与训练
  配置一致。无目标速度前馈；不能照旧源码注释把“加 dq 前馈”当作匹配训练。
- 机械臂部署 kd=7，而训练为 5，并有独立目标滤波。它们是现有差异，不在
  本轮移除，也不能据此认定是腿部问题的来源。
- 接管全部结束后的 76 个控制记录，其腿部目标能在邻近 100 ms 的已记录
  actor 目标中找到完全相同的整帧。该匹配不构成电机确认，也不是精确帧因果
  关联，但未见目标在这段再被额外缩小的证据。

训练归档中 FilteredJointPositionAction 的 `_raw_actions` 是 EMA 状态，
但默认 `mdp.last_action(params={})` 返回 ActionManager 的输入 action，
不是该 ActionTerm.raw_actions。不能只看类内注释就把部署历史改为 EMA。

## 分阶段结果

| 阶段 | 相对前进开始时间 | 记录数 | 含义 |
| --- | --- | ---: | --- |
| 腿部接管 | 0.000～1.732 s | 83 | 仍有附加接管偏置与阻尼过渡 |
| 腿已接管、臂仍过渡 | 1.750～2.260 s | 25 | 不能当作完整全身稳态 |
| 全部接管已释放 | 2.283～3.986 s | 81 | 仅约1.7秒，不是稳态/耐久验收 |
| 仍由 actor 减速 | 4.009～5.001 s | 48 | 不是额外正向请求预算 |

接管全部释放后，四个小腿目标活动幅度约 0.72～0.93 rad，反馈活动幅度
约 0.08～0.17 rad。目标—反馈偏差的均值约 0.27～0.33 rad，去均值后
RMS 仍约 0.18～0.23 rad。因此偏差不完全来自接管或静态承载；但短记录
不足以确定实机惯量、摩擦、驱动器限制或模型差异中的具体原因。活动幅度比
不是步态正确率或抬脚高度，没有独立地面位移/足端测量。

## 已定位的起步切换问题

进入运动时，代码立即令 leg_offset_scale=0，切换到策略 PD；与此同时，
最初位置目标仍为站立目标，等待策略首帧及1.5秒附加偏置释放。
结果是位置连续，但支撑 PD 请求不连续：

| 小腿 | 站立 Kp→运动 Kp | 最后站立记录 PD 请求 | 首个前进记录 PD 请求 |
| --- | --- | ---: | ---: |
| FR | 675→160 | 53.40 N·m | 13.32 N·m |
| FL | 675→160 | 57.27 N·m | 14.38 N·m |
| RR | 675→160 | 64.89 N·m | 16.18 N·m |
| RL | 675→160 | 68.61 N·m | 17.16 N·m |

将旧/新 PD 都放到首个运动记录的同一反馈姿态和速度下比较，新请求仍只剩
旧请求约23.9%，排除了比较时姿态变化本身造成差值的解释。tau_est 记录也
出现同方向下降，但它不是独立力矩传感器，不能当作驱动器确认。
随后约0.15秒内小腿反馈进一步屈曲。这与起步短暂下蹲/腿软相符。

这是一处具体的部署切换缺陷，值得优先处理；它不能独自解释接管结束后的
全部步态偏差，也不能据此批准提高运动速度或延长实机测试。

## 建议的单项修正方向（尚未部署）

首次有效策略帧到达前保留最后一个完整站立命令；之后用“支撑 PD 请求连续”
而非仅“角度连续”的接管方式。对 q、dq、增益、前馈项均做一致处理，并验证
初始目标未超安全范围，再平滑交还 actor。不要新增支撑力矩的同时又重复
添加同一份重力前馈，也不要改变 action history 来掩盖接管差异。

本次 JSON 中的 torque-equivalent target 只是同状态的代数反事实检验，不是
可以直接下发的关节指令；未验证接管全过程、目标范围、足端接触和力矩边界。
需要先做离线起步/停止/故障回归，再考虑独立候选版本实机短测。保持原版
可回退；不直接增加长期 Kp，不删除任何停止/故障门控，不据此启动重训。
