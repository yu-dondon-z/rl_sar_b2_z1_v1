# V2.4.6 终点停车：实现、验证与未解决项

2026-10-26。独立目录 `va15_visual_tcp_v246_endpoint_20261025`，不覆盖主程序。

## 结论

已实现“确认真实可见末端 → 缓存有限已观测尾段 → 用实测关节 FK 和局部
位姿跟踪后方虚拟 TCP → 提前减速 → 原支撑停车 → 站稳后持续复核”的候选。
机身先经过终点不算完成。自动停车不触发趴下，X/B/遥控故障仍优先。

**仍不能宣称实机精确终点停车已解决，实机行走入口保持关闭。**
真值位姿下可通过，但 IMU/关节实验位置估计存在累积漂移。已增加明确区分：
健康的本体估计不是物理终点精度证明，实机 `terminal_metric_verified=false`。
即使估计内到达并站稳，也只报告
`LOCAL ESTIMATED END / PHYSICAL TERMINAL UNVERIFIED`，不报告任务完成。

## 本次发现并修复

1. 旧固定前视行/短视野问题沿用V2.4.5修复，不外推看不见的路径。
2. 短一些的新视野曾把曲线末点反向追加到缓存，破坏路径弧长顺序。
   现在只追加有向前弧长、足够重叠的真实观测；断段不能拼接。
3. 真正末端要求RGB确实停止，且末端前有清晰地面；至少六个不同新帧、
   至少0.5秒、米制位置一致。ROI边缘、可见延续、间隙和明显遮挡不得作为末端。
4. 初始后方尚未看见时不能伪造缓存；TCP尚未对齐时继续依赖普通实时视觉，
   不授予盲走权。仅已确认且实际TCP至终点完整覆盖时进入有限尾段。
5. 丢掉已走过的历史缓存，但保留15cm已观测回摆余量；未走过部分仍保留
   原图像时间。45秒尾段、60秒有效片段、行程/姿态/通信限制不放宽。
6. 原Supervisor会把速度恢复为固定0.15m/s，导致减速命令失效；已把仅终点
   模式的限幅贯穿FSM和actor输入，不改普通入口或权重。
7. 0.02～0.07m/s在部分仿真条件下停滞。终点接近速度使用0.10～0.15m/s，
   限制变化率0.03m/s²，不是给所有摇杆加最低速度。
8. 旧6cm到达条件会在步态前摆峰值提前停车，站稳后仍差约7cm。
   现在同时检查当前实测TCP的沿轨误差1.5cm，再由原控制器停车；最终验收仍
   保持平面6.5cm、离地9cm±5cm、速度上界0.04m/s，且额外连续复核1秒。

## 真值测试与位置估计测试必须分开

使用实际VA15 actor、18关节动力学和原停止控制器，但像素为标定模型合成。
真值模式用仿真位姿；估计模式只把模拟IMU、关节和力矩提供给生产实验观察器。
真实位姿仅用于渲染与评分，不提供给估计控制器。

- 真值16例：5m/7m、直线/轻曲线、摩擦0.5/0.8/1，共12个正常终点；
  另有未知失线、相机中断、定位中断和X停止4例。
- 估计8例：5m/7m、直线/轻曲线、摩擦0.8，另有上述4类异常。
- 另保留原8例独立估计视觉/TCP回归和人工B趴下仿真。
- C++17项、Python54项、2005组模型FK对照以及保存的41张RGB均单独检查。
  实枪TCP、软管、真实图像末端准确率和硬件可靠性不在这些测试的证明范围内。

前一轮审计结果：真值16/16通过；正常停车物理误差约厘米级。
估计模式4/8通过的是异常停止，四个正常终点未达物理精度。
正常终点真实误差约18～21cm；初始坐标原点对齐后，本体位置累计误差约
29～38cm，而早先视觉投影的末端也有约9～20cm偏差。两者部分抵消，仍会
导致“估计内已到达、物理点已越过”。这不是关节FK精度不足，也不能用
降低终点门槛或扩大缓存来解决。

## 下一步需要什么

终点附近需要独立的视觉/定位校正，优先评估后视相机能否同时看到实际TCP
投影附近和真实终点，或接入经过验证的定位系统。要先确认视场、标定与误差，
不能仅把IMU积分坐标命名为“世界坐标”就认为问题已解决。

当前同步范围是独立源代码、私有离线二进制和相机预览；不启动运动、不替换
已用入口、不装枪或软管。板载验证结果和指纹见 `BOARD_SYNC_REPORT.md`。
