# VA15 V2.4.5：实测后修复固定前视行和曲线包的一致性

2026-10-25 独立候选，保留 V2.4.3/V2.4.4 和主程序。当前放行、板载指纹和验证只看 qualification.json、BOARD_SYNC_REPORT.md；继承的 PREPARATION/OFFLINE/HANDOFF/HOTFIX/REAL_BLIND 报告是历史，不是本版验收。

## 为什么 V2.4.4 仍然不能连续走

会话 outputs/va15_near_walk_zdktsu6h 确认 V2.4.4 已运行。10 次 R1+Y 中，4 次短暂启动，约 0.9～2.2 秒就停止，其余拒绝；没有形成连续行走。X/B、GetDown → Passive 和 exit=0 正常，操作者确认实际趴稳、退出、无枪/软管。

行走阶段相机处理最大约 159 ms，提速已生效；但 48 个行走阶段包中，19 个因为远端没有覆盖固定 v=820.8 行而无效。许多包仍有 200～222 px 的连续胶带、近远置信度很高，只是观察到的远端稍短。连续拒绝使旧有效图像最终超 500 ms，于是刚接管步态就停止。不能把静态相机预览无超时当成动态识别已解决。

## 本版改动

1. **前视点必须在本帧看见的连续曲线上**。优先保留 v=820.8，若观测范围稍短，就从曲线内部选择前视点，最大 v=885.6，并保留 12 px 的观测余量。不把没看见的行外推出来。连续长度仍至少 200 px、至少 25 点，置信度/宽度等约束不变。
2. **控制端按同一曲线的公共行判断身份**。前视行改变自然会改变光线角度，不能直接把不同距离的两个点当成换线。Python 和原生端使用同一有界行范围；共同观测不存在时拒绝，不推算隐藏点。
3. **重采样保留精确近点/前视锚点**。旧版弯曲路径按 8 px 等弧长采样后，前视点有时不再落在发出的折线上，触发原生 2 px 一致性拒绝。新增精确锚点，而不是放宽解析容差。
4. 沿用 V2.4.4 的 CPU channels-last、受约束曲线拟合和逐帧异步诊断，不换网络或权重。

VA15 model_5000、70 维观测/18 维动作、raw/EMA、关节路由、增益、Y 提前准备、首帧力矩连续、足端/停止条件、400 ms 处理预算、500 ms 图像时效和首次六帧均不改。确实失线/短路径仍停止，恢复图像不自动重启。

## 测试与边界

离线保存图像对照 41 张：旧固定行 22 张可用，新版 39 张可用，2 张仍拒绝；并非实机成功率。39 个支持路径和 2 个短路径已通过原生解析检查。原有可用图像没有退化。新增自适应行、锚点、换线/薄缝/过短观测等回归和物理仿真结果见 BOARD_SYNC_REPORT.md。

没有宣称实际行走、转弯、TCP 精度、带枪/软管或硬件已合格。仿真像素不是实际识别精度，实验性单目平地投影/IMU 关节无滑移估计不是深度或绝对定位。

## 人工短测

在 PC4 NoMachine 桌面终端，相机、控制和既有 Z1 服务同入口：

```bash
cd /home/unitree/rl_sar_b2_z1 || exit 1
bash diagnostics/va15_visual_tcp_v245_20261025/run_visual.sh eth0 --walk
```

保持无枪/软管，实际趴稳、旧控制退出，收臂和运动区域清空，防跌/遥控急停准备好。输入大写 RUN → A 起立 → 实际站稳后 Y → 等待机械臂准备与支撑就绪 → 确认黄/青点落在目标胶带而非瓷砖缝、持续 PATH IN RANGE → 按一次 R1+Y。

前进命令仍为 0.15 m/s，yaw 限制仍 ±0.06 rad/s，不推摇杆。首轮只短走约 2～3 秒，X 停止、B 趴下；实际趴稳且 Passive 后 Ctrl+C。若再出现抽动或马上停止，停止重复触发，保留当前会话路径；不要通过加速、增益或忽略故障继续。

视觉失效后完成停止，再明确 R1+Y 才能重启；无额外窗口 R、第二终端或自动恢复。较长一次才可能积累到后方 TCP 的真实观测历史，日志 active=1 代表目标接入，active=0 不伪造后方点。TCP 继续使用训练约 9 cm 目标，不强制 1 cm 接地。

--preview 只取相机，Q/Ctrl+C 结束；--shadow 则会人工接管站立但不行走，不是只读模式。P/L1+X 撤去主动支撑，非日常停止；不能在站立时用断电或强退替代停止。
