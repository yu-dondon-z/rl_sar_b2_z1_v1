# VA15 实机行走锁定排查：尚未安全解锁

## 已确认的两个缺口

1. **停止反馈依赖了低层接管后本来就不可用的官方状态消息。**
   [宇树官方说明](https://github.com/unitreerobotics/unitree_mujoco#supported-unitree-sdk2-messages)
   写明，实机关闭内置运动控制服务后不能读取 SportModeState；模拟器仍
   保留此消息。不能用模拟器的表现证明实机可用，也不能同时恢复官方
   运动控制与当前低层控制来抢夺控制权。
2. **当前原始足端桥路不能沿用一组阈值标定。**
   相近站姿、关节力矩下，部分通道相对于趴卧的变化方向跨轮次不同。
   这是无法通过现有数据得到可靠标定的证据，并不证明传感器硬件已损坏。
   不通过换符号、取绝对值、降低阈值或强制四足接触来解锁。

## 只读探针堆错误已定位并修复

PC4 普通交互式终端自动 source ROS Humble，导致旧探针将 ROS 的
`libddsc.so.0.10.4` 与宇树 SDK 的 C++ DDS 库混用。旧二进制带入该
环境可复现 `free(): invalid next size`；Memcheck 在
`ddsi_sertype_init_flags` 捕获了 72 字节对象末尾之外的 4 字节写入。
趴卧时拒绝初始化和高度/速度 NaN 与此堆损坏没有因果关系。

只更新独立诊断目录与 `scripts/check_b2_independent_state.sh`：固定
配套 DDS 库路径并校验实际加载路径，改用共享回调收件箱、显式关闭
native reader 后再释放监听器，支持信号收尾和报告最终退出码。
未修改生产控制器、FSM、策略配置或权重，也未修改系统 ROS 环境。

最终版本在相同 ROS 环境下通过 ASan/UBSan 24 项、普通运行 14 项退出
回归（含中断和错误路径）。Memcheck 非法访问检查为 0，确定/间接/
可能泄漏均 0；SDK 发现报文的未初始化字节告警另外保留，没有隐瞒为
全部内存问题均已解决。原有两项 CTest 通过。

完整证据和复验指令见独立诊断目录 README。本次修复只证明诊断工具
能够正确运行/退出，不产生运动资格，行走仍锁定。

## 后续：Z1 导致的 Ctrl+C 退出阻塞

站姿只读复核成功（985 帧，约 0.55 s 初始化，此后 931 帧持续有效），
用户按 B 后已进入 Passive，但 Ctrl+C 卡在 Z1 超时。发现 `z1_ctrl`
已退出成 zombie，而主程序析构仍调用没有超时的 `setFsm(PASSIVE)`。
两进程属于同一个前台进程组。

本阶段在操作者确认安全趴卧、Z1 收紧后清理了卡住的进程，并更新生产
代码的 Z1 启动/退出路径：隔离 Z1 终端进程组、使用退出专用有限次数
PASSIVE 请求，不再无限等回复。没有修改正常控制、VA15 权重/配置、
FSM、接触阈值或动态运动权限。板载已备份、编译、离线检查；没有替
操作者启动实机控制。该修改尚需一次趴卧状态的实际退出验证。

详见 `patches/va15_z1_exit_20261020/README.md`。原先“生产代码未动”
的结论仅描述此前估计器旁路阶段，不包含这次退出修复。
