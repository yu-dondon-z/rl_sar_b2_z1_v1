# VA15 V255：实机候选与 Z1 单一 I/O 所有者

日期：2026-10-28（Asia/Shanghai）

## 这次解决的问题

之前进入 `R1+Y` 后偶发剧烈抖动、重复启动无反应、退出后再次进入 Z1 模式失败，主要风险来自：

- Z1 SDK 的后台 `sendRecvThread` 与策略/控制线程同时读写 `lowcmd`、`recvState`；
- 控制线程直接调用可能长时间等待的 `setFsm(LOWCMD)`；
- `B/X/Ctrl+C` 退出时，停止请求、SDK 线程和 UDP 退出握手没有统一所有者。

V255 保留启动时一次 PASSIVE 握手，但运行时改为：

1. 策略线程只写一个 Z1 命令邮箱；
2. 独立的 `real_z1_io` 500 Hz 循环独占 SDK 缓冲、调用 `unitreeArm::sendRecv()`；
3. LOWCMD/PASSIVE 请求通过邮箱发送，读回状态后记录实际 FSM；
4. 退出先提交 PASSIVE、等待一个短窗口，再停止 Z1 I/O 循环；
5. 原策略、70/18 维观测、腿部增益、接触判定和后方 TCP 逻辑不改。
