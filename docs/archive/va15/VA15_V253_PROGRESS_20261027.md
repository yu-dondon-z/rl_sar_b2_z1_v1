## 用户明确的任务终点

**后方 TCP 到达裂缝线尾，再停车站立。** 不是前相机看见线尾就停，也不是机身先到线尾就算完成。

新候选流程：

```text
当前相机图像 → 同一裂缝的连续中心线 → 捕获时刻的标定位姿投影
    → 普通视觉行走，缓存实际看见的路径
    → 至少 6 个独立图像、跨越至少 0.5 秒确认同一空间线尾
    → 保存有限终点和实际观测终段
    → 后方 TCP 接近终点（可在前相机已越过线尾后继续）
    → 实测关节正运动学 + 当前局部位姿判断 TCP 到达
    → 请求原停止控制器停车
    → 重新确认 TCP 位置和四足静止支撑，保持站立
```

未知丢线不是“到达终点”。确认后的接近是一个独立有限目标控制阶段，不刷新过期相机时间、不伪造裂缝延长线。机身为把后置 TCP 携带到终点而继续前移，这是机身的规划运动，不是新增识别出的裂缝点。每次 R1+Y 显式启动/停止；X/B 和状态故障仍可中断。

## 本轮核实与修改

1. **真实图像拒识原因已定位。** 弱对比恢复分支把“与完整 RGB 暗区一致的边界”也误当成“裁剪较大暗区”，导致胶带仍存在时过早截断中心线。现在只拒绝真正裁断 RGB 连通暗区的网络小片段，不降低原有长路径、置信度、时效要求。
2. **保存图像对照。** 7 组、共 14 张图像，长路径有效数由 8 增至 10，没有退化，未生成假线尾；关键序号 489 的前/后图分别由 150/138 px 恢复为 354/348 px。它们是保存 JPEG 的网络推理，不是完整实时历史，不能证明板载延迟已解决。
3. **Z1 SDK 软件行为已实测。** 链接当前实际 SDK 的内存测试证明 LOWCMD 会重置此前写入的增益、被动命令缓冲不等于 FSM 已 PASSIVE、重复 LOWCMD 可能失败。测试内核阻止网络和创建进程，状态回复是内存模拟，不是实机回应。单所有者、有限超时模式协调器目前仅为 bench 原型，尚未接入实机发送路径，不能写成 SDK 问题已修好。
4. **新建后方 TCP 终点候选。** `production/visual_rear_completion.hpp`；旧的前相机提前停车测试仍保留并明确区分。终点必须在空间上重复一致；实际 TCP 来自实测关节 FK，而不是目标命令。
5. **不改变策略。** VA15 model_5000、70/18 维、原始上次动作、EMA、动作尺度、训练 PD 契约、接触判定及原四足停车条件保持。TCP 仍通过原 actor 目标观测输入，不叠加 IK 控制。

## 误差口径

接近阶段采用 5 cm 水平 / 5 cm 高度误差并保持 0.1 秒；停车后再要求 7 cm 水平 / 6 cm 高度误差，以及原四足静止门槛持续 0.5 秒。这是候选控制容差，不是硬件精度承诺。目标离地高度沿用该权重训练时的 9 cm，没有改成未训练的 1 cm。

当前还是光学相机、平面地面投影、IMU/关节局部估计，未接入深度。没有安装枪时，FK 对应模型中的**虚拟焊缝枪 TCP**，不等于已完成实际工具标定。

## 当前验证状态

最终结果：C++/原生无通信 **29/29**，Python **67/67**；新后方 TCP 物理检查 **5/7**，其中预期正常完成的直线、曲线 **0/2**，异常识别/人工停止 **5/5**。因此任务验收不通过。旧版的 11 项“前相机线尾停车”不能充当新目标通过证据。

两组都成功确认了 6 帧线尾，但 TCP 路径目标一直未激活，仍保持原待机目标。最小估计水平误差约 21～22 cm，该时刻真值误差约 27～30 cm、机身航向偏差约 15°；最终没有获得正常终点完成和原最终支撑停车资格。没有摔倒不能视为验收通过。

原始证据：`outputs/rear_endpoint_final/summary.json`、`diagnosis.json`、各用例 CSV。注意 summary 旧字段 `cap_frames=0` 统计的是“请求正常制动时的帧数”；本次没进入正常制动，真实线尾确认看 CSV `end_frames=6` 和 diagnosis。

中间失败探针完整保留在 `outputs/rear_endpoint_probe/`。其中把后方 TCP 横向误差直接送入前视转向公式会恶化航向，已撤销；后置点瞬时横向转动速度与前视点符号不同。不能照搬前视追踪公式，也不能放宽到达误差把失败写成成功。
