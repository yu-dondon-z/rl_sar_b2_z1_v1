# VA15 V254：后方 TCP 视觉行走修复记录

2026-10-27。已阅读另一帐号交接，并通过独立物理测试复核其结论；未直接把交接中的“通过”当作实机通过。

## 做了什么

新版本：`patches/va15_vision_completion_v254_20261027`。保留主程序、V251/V252/V253 及已有 VSCode 修改。VA15 model_5000 权重不变。

发现并修复三条可复现的问题链：

1. **TCP 目标根本没激活。** 部署端对不可达目标的拒绝，与该权重训练归档中的目标分配不同。恢复受限、平滑的训练工作区参考，同时保留真实裂缝目标；不能用裁剪后的参考冒充已到达。
2. **局部判断到达，实际还差一截。** 固定线尾投影与里程计尺度误差累计。改为线尾仍可见时持续一致性更新，并用多帧静止线尾相对位移估计有限沿程尺度，不用仿真世界真值做控制。
3. **四脚站住却抓不到停车参考。** 规划髋参考仅略超原包络也被整体拒绝。现在只将边界附近的小量规划参考投影回原包络，支撑与运动门槛、首次命令力矩连续性保持不变。

## 没有改什么

没有放宽实际接触、支撑、到达容差，也没有增加电机增益、改动作滤波/scale 或更换权重。TCP 离地目标保持该归档训练值 9 cm，未另改为 1 cm。停车规划参考的边界投影最多 0.02 rad，输出仍受原 0.15 rad 包络约束。

## 还不能宣称的事情

物理检查使用真实 actor，但相机输入是合成标定观测；实际分割网络不在物理闭环中。没有安装实体枪和软管，仅评分虚拟焊缝 TCP，因此不是实机精度或负载验收。

历史实机进入模式的约 5.9 Hz 抖动没有在此次物理测试中复现。真实 SDK 的收发并发、模式所有权、板载时序和连续相机识别仍需独立处理。单所有者 SDK 协调器仍是 bench 原型，不能说已接入真实控制。

**本轮未访问、同步或启动板载。** `simulation_pass=true`，但实机、行走和同步放行仍为 false。后续先完成实际 SDK 生命周期与板载无运动核验，再安排人工实机测试；不要直接改放行字段启动。
