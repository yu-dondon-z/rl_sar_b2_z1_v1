相邻稳定帧的工作点误差通常只有毫米级，错误帧是突变，并非固定安装矩阵的整体偏差。具体图像中误选了哪个结构尚未重渲染确认，不将其直接称作阴影误检。

## 2. 后视拒帧与底盘命令强耦合

当前`VD1VisualController._validate()`同时要求前后视觉有效，并要求后视覆盖工作点；任一检查失败，`update()`将底盘期望速度、角速度一起设为零，重置`_tracking_elapsed`。恢复后又执行2秒起步渐进。前视可用时也会受后视短线／缺口影响。

| 事件 | 第一次会话 | 第二次会话 |
| --- | --- | --- |
| 首次控制拒帧 | 10.04秒，倾斜1.28° | 10.70秒，倾斜2.91° |
| 首次拒帧原因 | 后视不覆盖x=-1.02 | 后视不覆盖x=-1.02 |
| 启动后首次倾斜超过8° | 10.50秒 | 12.18秒 |
| 最终倾斜停止 | 11.30秒 | 13.58秒 |

第一次10秒后的平均前进命令降到约0.094 m/s；第二次12秒后的平均命令降到约0.023 m/s。拒帧在明显失稳之前出现，但仅凭先后关系不能证明其独立导致摔倒。原VD1的可靠停车能力此前也未通过，这种反复低速／停车指令与策略能力不匹配。

还发现一些视觉包`valid=true`但后视根本不覆盖工作点，例如第二次`sequence=267`的后视范围约`[-1.421,-1.091] m`。它会被控制器进一步拒绝；因此“感知有效”与“控制可用”是两个层级，旧窗口没有完整展示后一个层级。

## 3. 捕获帧直接保持，存在控制延迟

稳定阶段被使用的已接受帧，距当前控制时刻平均约0.17–0.18秒仿真时间，常达到0.24–0.26秒；主机单调时钟帧龄约0.24–0.25秒。图像点仍在捕获时的机身坐标系，控制直接保持，没有使用IMU／运动估计将其更新到当前坐标系。

这里分别统计仿真时间和主机时间，不将两者混作同一时钟。拒帧时`status.source_sequence`仍是最后一次被接受的帧，旧日志不能用它识别本次被拒绝的输入。

## 4. 已排除和仍未排除的事项

第二次会话0–8秒的离线评价：前视路径点平均横向几何误差约3–5 mm，TCP视觉测量误差约1.7–1.8 mm，测得地面法向误差约0.06°。未见整体坐标轴符号或深度尺度错误。

第二次的末端目标在错误帧之前已经向负y边界逼近：约7.66秒超过`|y|=0.10 m`，约9.88秒超过`0.14 m`。因此错误帧不能解释更早的全部横向偏离。底盘转向跟踪、帧运动补偿、机械臂目标与步态耦合以及物理沟槽接触仍需分开判断。此前成功的真值实验使用连续平地、0.6 m前视；此次有物理裂缝且视觉可见近端通常约1.5 m，不能把两者仅视为换了一个点源。
