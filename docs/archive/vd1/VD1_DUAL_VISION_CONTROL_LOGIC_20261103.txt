VD1 前后视觉轨迹点选择与控制指令生成说明
日期：2026-11-03
文件编码：UTF-8

说明范围：本文整理当前 VS Code F5“双视觉＋同形裂缝”调试入口的实现，
对应 guarded 控制模式。当前场景最大曲率为 0.30/m，正常前进速度指令为
0.4 m/s。本文记录实现逻辑，不表示全部弯道、末端精度或实机能力均已验证。


一、整体流程与坐标约定
============================================================

前视负责观察前方裂缝，后视负责测地面、裂缝和工具 TCP 位置。
前后视共同估计底盘附近的路径，生成底盘转向指令；后视另行生成末端
位置目标。两类指令与 IMU、编码器数据一起交给原 VD1 actor 执行。

流程如下：

  后 RGBD ──> 测得地面平面、后视裂缝点、工具 TCP
                  │                 │
                  │                 ├──> 后方固定工作点 ──> 末端位姿目标
                  │                 │
                  └──> 前 RGB 投影   │
                            │       │
  前 RGB ──> RHANet 分割 ──> 前视组件选择与三维裂缝点
                            │       │
                            └───┬───┘
                                │
                    帧身份、时效、几何与后视连续性检查
                                │
                        前后视局部三次拟合
                                │
                       0.4～0.6 m 底盘引导点
                                │
                       前进速度、转向角速度指令
                                │
                 底盘指令＋末端目标＋IMU＋编码器
                                │
                          原 VD1 actor
                                │
                       18 个关节目标与 PD 执行

坐标约定：
  机身坐标 X 向前、Y 向左、Z 向上。
  相机光学坐标按 OpenCV/ROS 约定：右、下、前。
  相机标定负责将相机坐标转换到机身坐标。

图像换算出的 points_b 属于“图像捕获时刻的机身坐标系”。当前没有利用
运动估计将这些点补偿到控制执行时刻。

底盘融合引导点与末端目标是两套不同的目标：
  底盘：使用前后视融合估计的前方引导点。
  末端：使用后视裂缝在机身 x=-1.02 m 处的横向位置。


二、图像采集、同步与处理顺序
============================================================

MuJoCo 输出前 RGB、后 RGB，以及与后 RGB 对齐的深度图。
当前渲染分辨率为 640×480。

actor 每 0.02 秒执行一次，即 50 Hz；每隔两个 actor 步捕获一对图像，
即每 0.04 秒仿真时间捕获一次，名义捕获频率为 25 Hz。
视觉进程异步处理，实际视觉结果更新频率还受推理耗时影响。

每对图像携带：
  - 相同的 sequence 序号；
  - 相同的 capture_generation 捕获批次；
  - 原始 capture_timestamp 捕获时间戳；
  - 相机内参、外参和必要标定数据。

发布器会核对返回的视觉结果确实来自已发布的图像对。控制器继续检查
序号、捕获批次、同步性和时效，拒绝倒序、过期或刷新旧时间戳的结果。

后视先处理，因为前 RGB 没有深度，需要利用后 RGBD 测得的地面进行
三维投影。只要后视地面平面仍能测得，即使后视裂缝或 TCP 后续检测
失败，前视仍可能有效。


三、两路图像共用的裂缝分割和中心线提取
============================================================

1. RHANet 分割

当前默认使用 RHANet_dep，对 RGB 图像输出裂缝概率图与二值掩膜。
分割阈值为 0.90。桥接程序的默认网络输入尺寸为 360×640。

2. 图像区域筛选

在提取中心线前：
  - 根据地面几何限制允许的图像区域；
  - 去掉图像边缘 8 像素，减少边界伪线；
  - 去掉青色、品红色工具标记附近的像素；
  - 检查掩膜面积比例，允许范围为 0.0003～0.20。

3. 掩膜清理与中心线

  - 使用 3 像素形态学闭运算连接小缺口；
  - 删除面积小于 80 像素的连接组件；
  - 将裂缝区域细化为单像素骨架；
  - 在选中的骨架组件中，从靠近图像锚点的端点出发，沿骨架图提取主路径；
  - 使用 7 点窗口平滑；
  - 沿路径约每 6 像素重新采样一个轨迹点。

4. 提取后的基本检查

  - 至少 6 个轨迹点；
  - 像素路径长度至少 30 像素；
  - 轨迹点平均裂缝概率不低于 0.90。

控制使用的是经过筛选、平滑和采样的裂缝中心线，不是全部分割像素。


四、前视如何挑选裂缝组件并转换为三维点
============================================================

前视的组件选择已改为“优先选择测得前向覆盖最长的组件”。
这是最近为急弯场景加入的修正。

对每个清理后的候选连接组件：
  1. 排除图像高度小于 12 像素的组件；
  2. 单独提取中心线；
  3. 利用相机标定和后视测得地面，将中心线像素投影到机身坐标；
  4. 要求至少 6 个有效三维点，且 X 方向覆盖至少 0.30 m；
  5. 比较候选组件的 X 方向覆盖，选择覆盖最长者；
  6. 覆盖相同时，再比较组件到图像锚点的距离。

比较的是前向覆盖多少米，不是单纯比较组件面积或像素线长度。
该规则用于减少真实裂缝弯向画面一侧时，中央短伪线被优先选中的问题。

前视三维测量区域：
  0.10 < x <= 3.0 m。

实际最近能看到多远由安装角度和机身姿态决定，目前常见约为 1.5 m。

像素转三维的几何原理：
  - 使用相机内参，将像素 (u,v) 转成相机射线；
  - 使用外参，将射线变换到机身坐标；
  - 求射线与后视测得地面平面的交点。

用公式表示：
  r = K^(-1) [u,v,1]^T
  p_b = t + lambda * R*r
  lambda = -(n^T*t+d) / (n^T*R*r)

其中 K 为内参，R、t 为相机到机身变换，n、d 为测得地面平面参数。

前视没有独立测距，依赖“裂缝位于测得地面附近”的假设。
最终还检查至少 65% 的中心线射线能有效与测得地面相交。

前视局限：
  - 当前没有类似后视的跨帧轨迹跳变检查；
  - 最长前向覆盖也可能来自错误长线；
  - 当前不会在首选组件最终检查失败后，自动逐个尝试其他候选组件。

相关文件：scripts/vd1_visual_front.py。


五、后视如何得到地面、TCP 与裂缝三维路径
============================================================

1. 深度有效性

后深度必须与 RGB 对齐，按标定单位换算为米。
当前有效深度范围为 0.08～4.5 m。

2. 测量地面平面

每隔约 6 像素采样深度，反投影为机身坐标三维点。
用 RANSAC 找主要的近水平平面，再使用内点重新拟合。

主要检查：
  - 内点距离阈值 0.012 m；
  - 至少 100 个内点；
  - 支持比例至少 20%；
  - 平面倾斜及点的二维空间分布合理。

该地面平面来自后视深度，不使用已知世界地面高度。

3. 测量工具 TCP

通过颜色检测青色和品红色球形标记，用球面深度拟合球心。
检查球面拟合误差及两个球心间距，再利用标定换算 TCP。

当前仿真标定：
  - 球半径 0.035 m；
  - 两球沿工具轴线间距 0.06 m；
  - TCP 延伸量为 0，即青色球心对应 TCP。

得到的是由图像和深度测量的 TCP，不读取仿真真实 TCP。

4. 后视裂缝组件选择

后视仍沿用原中心线选择：优先选靠近画面中部偏下锚点的骨架组件。
锚点约为 (图像宽度中点, 0.65×图像高度)。
后视没有使用前视新增的“最长前向覆盖”选择规则。

5. 后视地面区域筛选

利用测得地面与深度：
  - 排除高出地面 0.015 m 以上的前景；
  - 对前景区域额外扩张约 4 像素，减少工具和腿边缘干扰；
  - 允许测得地面以下 0.10 m 内的沟槽区域。

6. 沿中心线取深度

对每个中心线像素，在 3×3 深度块内取有效深度中值；块内至少需要
3 个有效深度值。全部轨迹点的有效深度支持比例至少为 65%。

随后反投影成三维点，并将其正交投影到测得地面上。
因此，用于后续控制的是裂缝的地面投影线。

7. 前后视三维路径共用的检查

  - 至少 6 个有效点；
  - 相邻点间距离不超过 0.25 m；
  - 路径总长度至少 0.12 m。

后视还计算 TCP 地面投影到裂缝折线的最近距离，用于误差诊断。

相关文件：/home/dong/b2_z1/scripts/vision/dual_camera_perception.py。


六、前后视如何融合成底盘附近的局部路径
============================================================

只有前视有效、后视工作点有效且通过连续性检查后，才尝试融合。

1. 建立测得地面坐标

利用测得平面法向，将机身前向投影到地面，再构造地面左向。
将路径点转换为“地面前方／左方”坐标，减少机身横滚和俯仰对转向
几何的影响。融合还要求测得平面法向足够朝上，法向 Z 分量至少 0.85。

2. 选择两路局部支持段

后视：使用地面坐标中 x 在 -1.5～-0.4 m 的局部路径。
前视：使用最近可见点开始、向前约 1 m 的局部路径。

两段均要求至少 3 个点；后视 X 覆盖至少 0.15 m，前视至少 0.30 m。

3. 等量采样

两段分别沿 X 均匀采样 12 个点，共 24 个点。
这样避免某一路由于像素更密而在拟合中占据更大权重。

4. 局部三次拟合

  y(x) = a0 + a1*x + a2*x^2 + a3*x^3

使用 5 轮加权最小二乘，对大残差点降权。

5. 拟合有效性检查

  - 两路可见段必须夹住底盘附近与预设引导位置；
  - 前后可见段之间的间隔不超过 3 m；
  - 每段残差中位数不超过 0.015 m；
  - 每段残差 P90 不超过 0.035 m；
  - 在两相机之间的区间采样检查，曲率绝对值不超过 0.6/m；
  - 该区间斜率绝对值不超过 1。

相机之间看不到的线段是通过以上拟合估计出来的。
没有读取场景中的 sin^3 曲线，也没有读取世界位置来补齐路径。

相关文件：scripts/vd1_visual_path.py，paired_ground_guidance()。


七、曲率如何决定底盘引导距离
============================================================

从三次拟合计算机身处的局部曲率：

  kappa = y''(0) / [1+y'(0)^2]^(3/2)

当前引导距离：

  L = max(0.4, 0.6 / [1+3*max(abs(kappa)-0.15,0)])

举例：
  视觉估计局部曲率 <= 0.15/m：L = 0.60 m；
  视觉估计局部曲率约 0.30/m：L 约为 0.414 m；
  视觉估计局部曲率约 0.40/m：L = 0.40 m。

这里使用的是视觉拟合曲率，不是场景配置中的“最大曲率 0.30/m”。

最终底盘引导点为：
  P_L = (L, y(L))。

急弯缩短引导距离，可以提高对近处横向偏差的纠正力度。


八、引导点如何变成底盘速度与转向指令
============================================================

当前采用纯追踪公式：

  yaw_desired = clip(2*v_cmd*y_L / (x_L^2+y_L^2), -0.8, 0.8)

其中：
  v_cmd = 0.4 m/s；
  (x_L,y_L) 为底盘引导点；
  yaw_desired 单位为 rad/s。

目标在左侧时产生正角速度，向左转；在右侧时产生负角速度，向右转。

正常目标底盘指令：
  [vx,vy,yaw_rate] = [0.4,0,yaw_desired]。

起步渐进：
  s = min(有效跟踪累计时间/2秒,1)
  blend = s^2*(3-2*s)
  前进与转向期望值同时乘以 blend。

随后进行一阶滤波：
  command += (1-exp(-dt/tau))*(desired-command)

当前参数：
  - 控制周期 dt = 0.02 s；
  - 前进速度滤波时间常数 tau = 0.20 s；
  - 前后视融合有效时，角速度滤波 tau = 0.12 s；
  - 回退前视引导时，角速度滤波 tau = 0.20 s；
  - 无效指令减速时，使用 0.20 s 滤波；
  - vy 始终为 0。

目前没有根据弯道自动降低正常前进速度，也没有侧移纠偏指令。
底盘主要依靠转向消除横向偏差。

日志中的航向误差、横向误差没有作为额外独立增益项叠加；曲率也没有
再额外叠加一次前馈，避免与纯追踪公式重复计算。

速度指令与实际速度的区别：
  公式使用 0.4 m/s 指令，没有用实测速度闭环修正。
  最近 0.30/m 曲率运行中，正常行走阶段实际前进速度约 0.485 m/s，
  比指令高约 21%。这会影响理想转弯几何与实际响应之间的关系。

相关文件：scripts/vd1_visual_guard.py，update()。


九、后视如何生成末端位置和姿态目标
============================================================

这条流程独立于底盘三次拟合。

1. 取固定后方工作点

将后视裂缝点按 X 排序，要求路径覆盖：
  x = -1.02 m。

在该 X 位置线性插值得到裂缝横向位置 y_seam，构造名义目标：
  p_nominal = [-1.02,y_seam,-0.30]。

这里 -0.30 m 是机身坐标 Z，不是距地面 0.30 m。
测得平面用于裂缝投影和误差测量；当前没有根据地面法向设置固定工具
离地距离。

2. 叠加视觉 TCP 位置反馈

  feedback = 0.35*(p_nominal-p_TCP_measured)

X 方向反馈强制为 0，保持固定后方工作位置。
反馈向量的总长度限制为 0.03 m。

  p_raw = p_nominal+feedback

3. 工作空间限幅

  X：-1.08～-0.96 m
  Y：-0.15～ 0.15 m
  Z：-0.34～-0.26 m

4. 平滑和速率限制

使用 0.30 s 时间常数更新末端目标，并限制目标移动速度不超过
0.15 m/s，即每个 0.02 s actor 步最多移动 0.003 m。

初始位置目标由启动时编码器和模型正向运动学初始化，然后逐步过渡到
视觉生成的工作目标。

5. 姿态目标

末端姿态采用固定四元数，按 wxyz 顺序传入 actor。
对应固定轴 RPY 约为：
  [0, pi/2-0.45, pi]。

姿态不根据裂缝切线动态旋转。

因此，目前末端在固定后方工作位置追踪裂缝横向位置，不是沿整条
三维裂缝生成完整的末端轨迹。

相关文件：/home/dong/b2_z1/scripts/vision/vd1_control.py，_rear_geometry()。


十、异常、回退、保持与恢复
============================================================

1. 帧身份和时效检查

控制器检查：
  - schema 正确；
  - 两路属于同一捕获批次；
  - 两路序号相同；
  - 捕获时间差不超过 0.04 s；
  - 捕获帧龄不超过 1.0 s；
  - 序号和时间不倒退；
  - 重复序号不能更换捕获时间戳。

时间检查使用主机单调时钟，不把仿真时间当作主机时间。
控制输入还会递归检查并拒绝世界位姿、真值等禁止字段。

2. 后视工作点连续性检查

比较的是工作空间裁剪前，后视裂缝在 x=-1.02 m 的横向位置。

允许变化：
  abs(delta_y) <= 0.04+0.45*min(delta_t,0.25) m。

超出就拒绝该后视帧，避免目标裁剪掩盖大跳变。
重复读取同一拒绝帧不会因为等待而变成可信帧。

3. tracking

前后视均有效：
  - 融合成功：底盘追踪 0.4～0.6 m 的拟合引导点；
  - 融合失败：底盘回退到前视最近可见点；
  - 两种情况下，后视有效时仍更新末端目标。

前视回退点的生成：对最近可见约 1 m 的前视路径做稳健二次拟合，
取拟合内点中最近的可见点作为纯追踪参考。该点通常比融合引导点远，
因此回退后的纠偏能力会改变。

4. rear_hold

前视有效、后视暂时失效，且曾经正常跟踪：
  - 保持上一次末端目标；
  - 底盘继续使用当前有效前视转向；
  - 不因短暂后视丢失重新开始起步渐进。

保持期限为距“最后可信后视捕获”不超过 0.6 s 主机时间，已包含推理
延迟。它不是从发现失效后再额外保持 0.6 s。

5. stopped

前视失效、帧身份或时效检查失败，或者后视失效超出保持期限：
  - 期望前进速度和角速度设为零；
  - 通过原滤波逐渐减小指令；
  - 末端目标保持。

stopped 表示控制器请求减速，不代表物理底盘已经停住。

6. 恢复

停止后必须重新获得不同序号的连续有效捕获，达到恢复计数后才重新
起步。重复使用同一帧不增加恢复计数。

后视长期丢失时，还要先通过多个不同新帧确认路径连续性，再经过停止
恢复计数；因此完整恢复可能不止需要三帧。

初始 waiting 状态：尚无可信图像时不启动正常运动。

相关文件：scripts/vd1_visual_guard.py。


十一、视觉指令如何交给 actor 和关节控制
============================================================

视觉控制器输出：
  base_command_b = [vx,vy,yaw_rate]
  tool_pose_b = [x,y,z,qw,qx,qy,qz]

它们与 IMU、编码器及上一次动作组成 70 维观测：

  底盘速度指令：        3 维
  末端位姿目标：        7 维
  IMU 角速度：          3 维
  重力投影：            3 维
  关节位置偏差：       18 维
  关节速度：           18 维
  上一次 actor 动作：  18 维
  合计：               70 维

观测沿用原缩放约定，例如角速度乘 0.2、关节速度乘 0.05。

原 VD1 actor 以 50 Hz 输出 18 维动作，关节目标为：
  q_target = q_default+0.25*action。

随后由 200 Hz 关节控制执行，腿部使用 PD，机械臂使用仿真中的隐式
位置执行器。当前调试还保留已有的实验性速度约束模型。

actor 不直接接收：
  - 原始图像；
  - 全部裂缝点；
  - 完整拟合曲线；
  - 仿真世界位姿或真实 TCP；
  - 实际底盘线速度反馈。

它接收的是视觉外环生成的底盘和末端指令，以及原有本体观测。

相关文件：scripts/run_vd1_mujoco.py。


十二、当前仍存在的实现限制
============================================================

1. 前视缺少跨帧轨迹连续性检查。
   最长前向覆盖可以减少短伪线误选，但不能保证长错误线被排除。

2. 捕获坐标中的点尚未运动补偿。
   图像推理和传输存在延迟；控制使用的点仍对应捕获时刻的机身坐标。

3. 正常前进速度没有闭环校正，也没有按弯道自动调速。
   0.4 m/s 是策略指令，不等于实际行走速度。

4. 融合失败时会回退到较远的前视可见点。
   该回退改变了引导距离和近处纠偏能力。

5. 末端工作区有限，高度和姿态采用固定机身目标约定。
   它不是完整的沿地面法向保持距离、沿裂缝切线调整姿态的轨迹控制。

6. 停止保护是指令状态。
   当前策略的物理停车和恢复表现需要单独验证。

7. 世界真值仅用于场景生成和独立评价。
   视觉控制器没有用解析场景曲线、真实底盘位置或真实 TCP 作为在线
   兜底。独立评价中的实际速度也没有回传到当前控制环。
